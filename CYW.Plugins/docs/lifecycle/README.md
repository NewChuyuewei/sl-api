## 4. 验证框架

- **方法图例**：`T` 离服单元测试 ｜ `D` 实机演示（目标环境） ｜ `R` 审查 ｜ `A` 分析。
- **判定原则**：工具与测试的输出是**辅助证据**；**最终验收判定始终以目标环境（真实 SCP:SL 服务器）演示为准**。
- **覆盖率**：Core 层以 coverlet 测量（`dotnet test --collect:"XPlat Code Coverage"`），数字作为**棘轮**（只许升不许降，见 `CONSTRAINTS.md`）；插件层以实机演示覆盖（不追求行覆盖数字，追求需求级演示证据）。
- **验证的验证**：定期执行**变异抽查**——人为反转一处条件，确认相关测试确实变红，再恢复。记录于验证记录。
- **稳健性测试**：边界与故障注入（损坏输入、空值、越界版本、异常注入）必须有过至少一次实机或单测演练。

## 5. 配置管理（SCMP 等比）

- **版本控制**：git，单一主线 `main`；每次提交即一次配置项变更记录。
- **基线**：每个检查点（CP0/CP1/…）达成后打**注释标签**作为基准（Baseline）；基线一经建立，其验证证据归档不再修改（勘误新增条目除外）。
  - 当前基线：`v0.1.0-phase1`（DO-178C 优化轮完成后建立）
- **变更控制**：
  - 需求变更 → 先改 `requirements.md`（人工批准）→ 实现 → 同一提交内补证据；
  - 紧急修复 → 可先实现，但**同一提交**必须回填需求与证据；
  - 破坏基线的行为变更 → 旧证据标记失效，重新收集。
- **可复现构建**：
  - .NET SDK 主版本固定（当前 10.x）；NuGet 依赖全部**显式钉死版本**（无浮动范围）；`packages.lock.json` 策略：单人阶段使用钉死版本 + 提交 `obj/project.assets.json` 不入库（评估中→列入遗留项）；
  - 目标环境（游戏版本/LabAPI 版本）记录于每次验证记录；
  - 环境变量 `SL_REFERENCES` 与部署布局见 `docs/dev/test-server.md`。

## 6. 质量保证（SQA 等比）

- **评审**：阶段性产出执行五轴评审（正确性/可读性/架构/安全/性能），发现项分级（Critical/Required/Optional/Nit）并记录处置，见 `verification-records.md` VR-006。
- **楼层规则**（始终强制，见 `CONSTRAINTS.md`）：零警告构建、无临时/验证代码入库、无未登记行为、公开 API 必有 XML 文档、无密钥入源码。
- **不合格品（Nonconformance）处理**：发现问题 → 记录（ID/证据/严重度）→ 修复 → 回归证据；**禁止静默修正**。
- **依赖纪律**：新增依赖必须评审（必要性/维护性/许可证/漏洞）；升级逐个进行并跑全测试。
